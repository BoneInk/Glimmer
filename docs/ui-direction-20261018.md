# Glimmer：沉浸式界面方向

研究日期：2026-10-18。范围：读取现有 SwiftUI 视图，核对 Apple 官方设计资料与壁纸应用原作者资料，提出可以直接实现的布局方案。本次研究没有启动应用，没有访问 Steam 账户、Keychain 或用户数据，没有测试实际锁屏，也没有修改生产源码。下述尺寸是本项目建议，不是 Apple 强制规范。

## 建议方向

把界面做成「一张安静的壁纸画布，两组悬浮控制」。根背景继续使用当前壁纸中上部的静态裁剪、渐变模糊；左侧只保留导航和收起的桌面控制；右侧顶部只保留当前任务需要的搜索/筛选。图片、标题、下载状态属于内容，不再分别包一层厚玻璃。沉浸感主要来自图片面积、留白和稳定层次，不需要更多折射面或更多动态背景。

用户已确定的约束直接作为基线：发现页取消「发现/链接 ID/下载管理」顶部分段；下载只由 sidebar 进入；主窗口各页面 titlebar 不显示页面文字；账号放右侧中性 badge，打开登录 sheet；壁纸标题浮在图内底部；下载显示真实 bytes；暂停与完成不显示进度 ring；所有来源保留「详情与设置」路径。

## 现有源码观察

读取文件：`AppWorkspaceView.swift`、`LibraryWorkspaceView.swift`、`LibraryGridView.swift`、`WallpaperCardView.swift`、`GlassStyle.swift`、`WallpaperWorkspaceBackdrop.swift`、`WorkshopSearchView.swift`、`WorkshopDownloadsView.swift`、`WorkshopGlassAppearance.swift`、`GWSettingsView.swift`。开发与研究同步进行，行号和局部实现可能在本文完成前后变化。

- 根视图已有单一 `NavigationSplitView`、共享静态壁纸背景和 200–260 pt sidebar。这一结构适合保留。根窗口标题 `Glimmer` 与播放列表/设置包装的标题需统一隐藏可见窗口文字，同时保留窗口可访问名称。
- `GlassStyle.panelBackground` 与 `workshopGlassSurface` 都是真实 `.glassEffect(.regular)`，同时再加边框和阴影。它们适合独立功能面，不适合所有内容块。已有 `groupedBackground` 可用于玻璃内部的普通分组。
- 素材卡片已把标题和按钮放进图内、单击打开详情、应用必须显式触发。这是正确基础。现有来源、格式/时长、分辨率、文件大小共多组信息会竞争封面；应减少常驻元数据。
- 发现页搜索外壳内部账号 badge、按钮、排序、时期按钮再次 glass；最近搜索标签、已保存说明还各自成独立面。删除这些「外壳内的壳」比增加特效更有价值。
- 下载当前存在 `.background(Color(nsColor: .windowBackgroundColor))`，会盖掉共享壁纸背景。仅在降低透明度模式使用实色；常态继承根背景。卡片可用局部暗化保证下载状态可读。
- 设置已有 780 pt 上限和收起的「存储与高级工具」，方向合理；`设置 + 版本号` 的正文大标题可以去掉，版本移入最末关于行。

## 通用布局和材料预算

### 四层足够

1. **背景层**：共享静态壁纸局部；不增加实时预览、视差、持续取帧或随滚动更新图片。其上仅一层稳定对比度 wash。
2. **内容层**：封面网格、文字、设置行、状态与错误。透明容器或普通低对比填充，无整页 glass，无反复描边阴影。
3. **功能层**：独立 sidebar、顶部搜索控制、一组正在操作的悬浮按钮。使用 regular glass；单个玻璃面内部改用普通填充、透明、分隔线，避免嵌套折射。
4. **临时层**：popover、sheet、菜单，由系统材料承担可读性。账号 sheet 与详情窗口复用既有逻辑。

玻璃计量按「独立功能区域」判断，不把页面上每个 capsule 都变成玻璃。内容分组主要通过 16–24 pt 间距表达，线条只用在需要区分的设置行；强颜色只表示选中、主操作、故障或确实进行中的工作。常态账号为 secondary，不使用绿色大块在线提示。

### 尺寸和文字

| 部位 | 建议 |
| --- | --- |
| sidebar | 200–220 pt，外侧边距 12，顶部 10；导航与桌面控制两组，间距 14；桌面控制默认收起 |
| 主内容左右边距 | 标准 24，紧凑 20；各页统一，避免发现 20 / 素材 24 / 下载 18 的跳变 |
| 搜索控件 | 高 42–46，主文字 13–14 pt；最大内容宽度 1440；搜索框可伸缩，右侧仅筛选/排序/账号 |
| 图卡 | 约 1.5:1；最小 280，合理上限 460；网格间距 20；圆角 20–22；标题距下边 16–18 |
| 卡片标题 | 16–17 pt semibold，最多两行；下面仅一行 11–12 pt 次信息 |
| 顶部到第一行图片 | 标准发现状态目标 120–180 pt；搜索结果状态约 80–120 pt；不出现长引导或大 hero |
| 设置内容 | 最大 740–780 pt；组间 24，行高至少 44；文字行优先，不为每个开关单独 glass |

页面标题已经由 sidebar 选中态说明。发现、全部壁纸、下载管理、设置不再各放一遍大标题；保留「收藏」「正在下载」等用于解释内容分区的短标题。

## 四页可执行设计

### 发现

顶部一条搜索：`[放大镜 搜索壁纸、风格或主题……] [筛选 2] [排序] [账号]`。输入支持 Return；搜索进行中原按钮转换为停止，不额外推挤一排常驻按钮。窄时保持搜索独占第一行，下行只有筛选、排序、账号，不能压到搜索框小于 240 pt。搜索外壳是一个玻璃面，内控件用系统样式或普通填充。

发现状态在下面显示单行主题词/趋势时期，最多一行，内容超出横向滚动；`最近搜索` 只在输入聚焦或尚未执行搜索时出现一行，不能在每次结果上方占一块。已保存展示成普通标题和横向小封面，只在发现且已有收藏时出现；`仅保存在本机` 放到帮助/说明，不作为一个独立玻璃面。

网格直接开始。封面上常驻标题、一个类型/时长标记；收藏和下载操作清楚可达。下载后进入对应详情/设置的行为沿用现有 coordinator。`热门/最新/本周` 一类排序反馈保留短文字，不新增「为你探索灵感」类大段文案。

空查询首次加载显示稳定占位卡，避免一张中央 spinner 占满空白；已有结果刷新时保留旧结果，只在搜索控件内标记正在加载。无结果：「没有找到作品」+「清除筛选」；网络失败：「暂时无法获取作品」+重试，具体错误放可展开区域。搜索已停止有独立空状态，不能伪装成无结果。

链接/ID 的进入方式是产品交互决定：本轮保持已移除顶部 tab；后续可将粘贴链接/ID 收在搜索框解析或 `… > 通过链接打开`，需要明确搜索与精确查找的优先级后再做。

### 素材库

顶部沿用同形搜索，右侧仅导入与排序。`创意工坊` 已在 sidebar，可从常驻 toolbar 移除；维护动作如刷新状态、清缩略图缓存收进 `…`。全局「应用到全部显示器」容易对隐式第一项生效，应以显式所选项为前提；没有主动选择时不悄悄应用第一张。

网格保持封面中心；常态图上只显示标题、一种必要的类型/时长、收藏与应用。来源常驻文字可移除，因为 sidebar 已有来源筛选；分辨率与大小移到详情。文件丢失例外：显示清晰警告，应用禁用，详情仍可进入以修复。键盘 focus/selection 和详情打开分别处理，焦点不能自动应用。

单击封面始终打开统一详情与设置；应用按钮始终显式，不能靠 double click 改桌面。hover 可增强按钮或显示 `…`，但详情、应用不应只能靠 hover 才找得到；键盘 focus 必须显出等价操作。空库只留「导入」和「浏览壁纸」两项，无常驻教学卡；拖拽时临时出现导入覆盖层。

### 下载

顶部是轻量筛选「全部 / 进行中 / 已暂停 / 已完成 / 失败」加 `…` 批量动作。此处分段属于状态筛选，不是已移除的发现页二级导航，可以保留。默认内容为封面卡片网格；根背景透出，卡片下部渐暗支撑文字，卡片不再有额外大玻璃面。

| 状态 | 图卡可见信息 | 进度/动作 |
| --- | --- | --- |
| 排队 | 标题、排队中 | 无假百分比；允许取消/队列控制 |
| 下载 | 标题、`已下载 bytes / 总 bytes`，有可靠速率时显示 | 单条真实线性进度或一个真实 ring，二选一；暂停明确可达；总大小未知时显示已收 bytes 和不定进度 |
| 正在暂停 | 正在暂停 | 控制暂时禁用，不能提前显示已暂停 |
| 已暂停 | 标题、已暂停、保留的 bytes | 无 ring；保留静态数值；继续按钮 |
| 校验 | 正在校验 | 独立不定进度，不能继续沿用下载 100% 当校验百分比 |
| 完成 | 标题、已完成 | 无 ring；详情与设置、应用/预览按已有能力提供；不能仅因文件存在就提前判成功 |
| 失败 | 下载失败与可读短原因 | 重试；需要账户处理时给检查账号；详细日志收进 disclosure |

进度只能来自真实传输统计；远端作品大小可作元数据，不能拿估计下载量伪装计数。暂停/完成无 ring 是已确定需求。当前队列的暂停控制必须继续称「暂停后续下载」以免暗示会中止正在传输项；单项暂停与队列暂停不可混为同一种状态。

### 设置

一个安静的纵向表单，宽度上限 780。第一组「外观」，第二组「启动与播放」，第三组电源策略；播放列表给摘要和跳转；存储、配置导入导出、诊断和恢复默认仍收进高级 disclosure。不要再嵌套一套左侧导航。

设置组用普通填充/标准 material，行内系统 Toggle/Picker；组标题在表单中承担导航，不加背景 pill。去掉页顶「设置」和大版本说明；末尾关于行保留应用名、版本、反馈。通常只显示选项当前值，需要解释的行为用一行 caption 或帮助，不让默认值说明占两三行。

删除、清理、恢复、授权边界属于有意义的文案，保留在确认/具体操作处：会不会移走原文件、是否停止正在使用的桌面、能否恢复必须明确。诊断路径、队列协议、原生会话等实现名留在诊断页，不出现在普通选择流程。

## 宽窄适配

本轮保留现有主窗口最小 1000×640，不为了「适配」突然降低最小宽度。内容区约 720–760 时至少两列 280 pt 卡，搜索工具必要时换为两行；约 980 以上可三列，约 1280 以上可四列。按实际内容可用宽度计算：`列数 = floor((可用宽度 + 20) / (280 + 20))`；卡片宽度均分，避免两张卡拉到过宽。最后一行左对齐。

窗口变大只增加列数/边缘留白，不无限放大字体。详情视图另维持它自己的最小宽度与滚动。未来若需要小于 1000 pt 的窗口，应单独决定 sidebar 自动折叠、单列模式和详情呈现；这属于产品决定，本轮不能通过删 `minWidth` 顺手引入。

## 最值得当下加入的五项小改动

1. **统一顶边和左右节奏**（布局）：主窗口去可见 titlebar 文字，搜索/网格左右统一 24/20，首屏去重复大标题。触点：`AppWorkspaceView`、各页 header。不改导航目的地和行为。
2. **去掉玻璃内的二次玻璃**（视觉）：搜索外壳内账号/排序/趋势/历史不再各加自定义 glass；内容分组用普通填充；下载常态背景透明。触点：`WorkshopSearchView`、`WorkshopGlassAppearance`、`WorkshopDownloadsView`。保留降透明/高对比降级。
3. **把发现页先还给图片**（布局与少量可见性状态）：最近搜索一行/输入时出现，高级筛选维持 popover，去历史/保存说明壳。触点：`WorkshopSearchView`。不新增 hero，不新增数据源。
4. **统一图内标题与卡片元数据预算**（布局与文案）：标题+一行关键类型/时长；来源、尺寸、大小进详情；所有卡都保留详情与设置。触点：`WallpaperCardView` 与工坊封面组件。下载中的 bytes 不受此删减影响。
5. **明确下载的阶段**（状态呈现，已有用户授权）：下载只呈现真实 bytes；暂停/完成没有 ring；校验独立表现；异常只露可读短原因，完整日志收起。触点：下载展示与 presentation helpers，不改变下载调度语义。

需要另作产品决定：是否新增大推荐 hero；链接/ID 在搜索框内如何解析；是否允许小于 1000 pt 窗口；是否把跨显示器应用入口提升为固定底栏；是否为首次进入默认选择素材。以上不作为本轮视觉整理的隐式副作用。

## 视觉验收点

可使用现有隔离 UI review/合成素材机制；不要为了看布局改动实际桌面或锁屏。核对明亮高细节背景、深色背景、降透明、减少动态、错误/空/加载、长中文标题和最窄窗口。所有控件有 keyboard focus、accessibility label，颜色之外有文字/符号表示状态；图内文字在白色封面上仍可读；悬浮文字不遮住唯一主图主体；点击封面不会应用。
