# Scene 通用引擎与升级规则

生产版的全部 Scene 通过同一个 `SceneWallpaperRuntime` 门面进入独立进程的社区 Metal 后端。下载、导入、详情与桌面播放不按 Workshop ID 选择补丁；旧有限渲染器只保留供隔离测试和缺失后端包的回退使用。

## 新作品的正常路径

1. Steam 下载原始项目，检查入口、完整文件树和内容哈希。
2. 首次需要公共运行资源时，经正常 Steam 会话获取并逐文件校验，发布应用私有收据。后续作品复用同一已验证资源包。
3. 播放时由通用后端解析原始图层、材质、着色器和脚本，检查真实 GPU 管线与资源就绪状态。
4. 缺少真正支持的能力时明确报告兼容性问题，不以静态封面或忽略特效冒充成功播放。

公共资源缓存与第三方代码分离：官方资源及用户作品不随 App 或源码归档分发。应用不保存 Steam 密码，保存会话仍由钥匙串和现有稳定签名身份管理。

## 后续引擎升级

后端固定来源为 `deepratna-awale/open-wallpaper-engine-mac`，初始上游提交为 `8d9e86d16e87395d0ab46710b05ecc24fd992539`。后续缺失特性在通用解析器、着色器转换器或渲染模块中实现；同一引擎升级应同时惠及使用该能力的所有作品，不增加壁纸名称、ID 或内容哈希分支。

每次升级更新 Vendor 来源记录、对应源码归档和第三方许可，并经过以下验收后随 App 一起发布：

- 真实原始作品的脚本、着色器、粒子、内嵌视频与文字；不改动作者素材。
- 无静态封面替代、无未声明的运行时 fallback；暂停、恢复和销毁正常。
- 正式签名 App 的真实 XPC/IOSurface 路径，而非仅研究探针。
- 帧率和适配实时更新，不重置同一会话的时钟，不因拖动帧率滑块重启辅助进程。
- 多实例隔离、过期帧拒绝、进程退出确认、签名调用者限制和私有资源路径检查。

这是一条统一扩展能力的实现路径，不是所有 Wallpaper Engine 特性的兼容承诺。当前未经验证的 3D 模型/骨骼、音频响应和 Windows 视觉等价仍需独立实现及验收。已有两张原作通过的结果不能外推为所有 Scene 均可播放。

当前构建、实装与界面验收状态以仓库根目录 `delivery-status.json` 为准。研究与真实后端验收见 `evidence/scene-backend-integration/acceptance-report.json`，正式客户端验收另行记录，二者不得混用。
