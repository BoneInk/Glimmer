# Legacy bounded 2D Scene and SceneScript subset

The production App now routes Scene projects through the shared community Metal/XPC backend. See the current [integration rules](../../../docs/scene-engine-integration.md) and [compatibility matrix](../../../docs/scene-backend-compatibility-matrix.md). The implementation notes and historical acceptance records below describe the earlier bounded inspector/compositor and its isolated tests, not the current production renderer's complete capability set. References to `evidence/` are local historical records and are not shipped in the Git repository.

This is a bounded reader/inspector, native 2D image compositor and restricted SceneScript runtime with bounded static modules. Static image scenes and supported scripted 2D layer updates are implemented; this is not full Wallpaper Engine Scene compatibility. Dynamic module loading, unimplemented events/APIs, custom shaders/effects, particles, audio/audio visualization, 3D, timeline/puppet animation and other unimplemented APIs remain unsupported. Blocking diagnostics prevent incomplete scenes from being presented as fully supported.

The historical checkpoint for this subset is 0.12.0 build 1. Isolated process/pixel tests and native CUA checks of the original geometric SceneScript fixture establish only the recognized subset. Exact installed hashes, retained user data and remaining acceptance work are recorded in delivery-status.json and evidence/scene-parent-installed-update.json.

The 0.12.0 build1 test package adds the parent-hierarchy capabilities below. The real-helper/two-virtual-display [30-check integration](../../../evidence/scene-parent-integration/result.json), [115-check helper probe](../../../evidence/scene-script-hierarchy.json), and [native UI review](../../../evidence/scene-parent-native-review/result.json) cover the stated subset. The installed 0.12 update preserves the latest post-quit user data and lock-screen state; physical multi-display presentation and Windows visual parity remain unaccepted.

`SceneWallpaperInspector.inspect(projectURL:propertiesJSON:limits:)` reads a local `project.json`, a loose scene entry or its adjacent `scene.pkg`, and resolves each image's model JSON → material JSON → `materials/<texture-reference>.tex`. Missing dependencies are diagnostics. Project defaults and direct `{user: "propertyKey", value: ...}` bindings resolve bool visibility, normalized RGB tint and numeric opacity (and type-compatible transform values). Recognized inline `{script: "source", value: ...}` wrappers are extracted only on `origin`, `angles`, `scale`, `size`, `visible`, `color` and `alpha`. Optional `user` and `scriptproperties` bindings are retained in an ordered `scriptProgram`; source text is never guessed to be a file path. Unsupported conditional/expression wrappers and scripts elsewhere remain diagnostics. Overrides accept a JSON dictionary of raw values or `{value: ...}` definitions. Extraction is not execution or syntax validation: the isolated helper performs actual JavaScript parsing/compilation before a runtime can acknowledge pixels.

`SceneWallpaperInspection` provides canvasSize, clearColor, layers in scene array order, textures, diagnostics and isRenderableSubset. Coordinates are 2D scene pixels with y up; origin is local to the parent (or the canvas for roots), anglesDegrees uses only Z rotation, scale uses XY, size uses pixels, tint is normalized RGB, opacity is 0...1. Layers retain parentID and isTransformOnly. Texture data is encoded PNG/JPEG or tightly packed straight RGBA8888 rows, with storageWidth/storageHeight and the real top-left imageWidth/imageHeight crop. TEX sampling flags are exposed (bit0 nearest; bit1 clamp). Non-centered alignment, nonzero pivot, camera parallax/shake, HDR, unrecognized material state and unrecognized behavior produce diagnostics. One explicit translucent/additive genericimage/genericimage2/genericimage4 pass and one static texture are accepted when combos/constants are empty and explicit cull/depth state is nocull/disabled. Additive blending adds source RGB times source/layer alpha to destination RGB; validated blend metadata survives isolated script updates. Nonempty combos/constants and non-default state remain blocking. Particle and procedural shape nodes are diagnosed as unsupported drawables rather than inert groups, and missing referenced particle textures are reported separately.

`SceneWallpaperRenderer.render(inspection:pixelSize:) -> CGImage` decodes the real PNG/JPEG/RGBA textures and composes centered quads with visibility, y-up origin, Z degrees, signed XY scale, top-left padded crop, normalized per-channel tint and combined texture/layer alpha. It uses source-over or additive blending in sRGB through public CoreGraphics, aspect-fits the canvas into the requested output, and refuses all diagnostics. Output is limited to 8192 per dimension and 16 million total pixels. Each call produces one raster frame of the recognized unlit image pass; the runtime composes successive validated script frames with the same renderer. Windows shader/color-space parity is unverified. `SceneWallpaperCanvasView.setInspection(_:) throws` is the lightweight NSView adapter; raster work runs off-main, cancels on replacement/detach, and rejects stale resize results. The temporary static inspection tool creates no player or periodic task and directs scripted projects to the library runtime instead of displaying unevaluated initial values. Earlier native CUA acceptance selected an original LZ4+DXT1/5 static fixture and toggled its real image layer; that evidence does not establish native SceneScript acceptance.

`ScenePackageArchive` uses signed-range-compatible little-endian indices, validates paths, case/Unicode aliases, counts, index limits, non-overlapping payload spans and truncation. `read(path:maximumBytes:)` uses bounded pread and never extracts archive entries. Loose reads use root-relative openat/O_NOFOLLOW. Limits default to 2 GiB archive, 20,000 entries, 16 MiB index, 64 MiB entry, 4 MiB JSON, 512 layers, 128 MiB retained texture bytes, 32 million pixels per texture and 64 million total texture pixels. Files are not immutable against writes by another process; truncation is detected, but this is not an OS sandbox.

TEX support follows the verified TEXV0005/TEXI0001 header and TEXB0001/2/3 and static TEXB0004 container layout. One static image, bounded mipmaps, raw RGBA8888, embedded PNG/JPEG and DXT1/3/5 (BC1/2/3) are decoded. TEXB0002/3/4 independent raw LZ4 blocks are structurally validated and decompressed before the image codec; decoded size and remaining aggregate texture budget are enforced. TEXB0004 is accepted only with an explicit zero media/video flag; its mipmaps follow the B3 layout, as specified by the pinned RePKG container reader. TEXB0004 video/nonzero media flags and unknown versions/sections are explicitly refused. Single-image TEXS0003 particle atlases now retain up to 256 bounded, axis-aligned equal-size frame rectangles, with image and storage sizes required to match; rotated/cross-image atlases and animated image-layer textures remain unsupported. Particle sprite sequences follow per-particle lifetime with adjacent-frame blending, rather than displaying the whole sheet or freezing its first frame. There is no signature scanning or guessed mipmap offset. Raw R8 (format 9) and RG88 (format 8) samples now expand to RGBA with zero absent channels and opaque alpha, retaining their original channel count for shader data handling. Noise and normal maps are sampled as raw data rather than receiving an sRGB transfer. This intentionally supports fewer files than upstream RePKG.

## Static modules and built-in utilities

An inline property script is a module entry point. It can use static named, default, namespace and side-effect imports. Project modules support ordinary exports, named re-exports, `export *`, live imported bindings and cyclic dependencies within the linked graph. Missing or ambiguous imports/re-exports and access to uninitialized bindings fail rather than receiving synthetic values. Ordinary helper, variable and default exports are permitted at the root; only the implemented `init`, `update` and `applyUserProperties` events are invoked. Known unsupported official events are explicitly rejected. This is the tested synchronous module subset, not a claim of complete ECMAScript module or Windows runtime parity.

The linker resolves only the three built-in module names and exact `.js` paths in the captured project snapshot. Relative paths stay within that root; there is no network, arbitrary filesystem, package-manager resolution or inferred proprietary built-in asset. Each script's graph evaluates referenced dependencies, with live bindings and cycle handling. Unreferenced files are not parsed or executed, so an unused JavaScript syntax error alone does not fail the graph.

Snapshot collection still inventories the project before linking: at most 128 candidate `.js` files, 256 KiB of UTF-8 source per file, and 1 MiB total across all inline scripts plus **all** candidate JavaScript files. Inline bindings retain the separate 64-binding/per-binding 256 KiB limits. The encoded complete worker request is capped at 2 MiB. Loose traversal is root-relative and no-follow, with 20,000 directory entries and 32 path components; symbolic links encountered in that inventory, case/Unicode aliases, noncanonical paths, non-UTF-8/NUL source or candidates over budget are explicit failures even when the offending module is unused. This eager safety inventory deliberately reduces compatibility with some otherwise valid projects. PKG projects take modules only from the archive; neighboring loose files never overlay missing or existing package modules. An immutable captured source dictionary is sent to the worker; the JavaScript linker cannot reopen source paths.

The original utility factory receives the worker's own `Vec2`/`Vec3` constructors, returns those vector types without changing arguments, and freezes its module namespaces:

- [`WEMath`](https://docs.wallpaperengine.io/en/scene/scenescript/reference/module/WEMath.html): numeric `deg2rad`/`rad2deg` factors, `smoothStep(min,max,value)` and `mix(a,b,value)`.
- [`WEColor`](https://docs.wallpaperengine.io/en/scene/scenescript/reference/module/WEColor.html): normalized `rgb2hsv`/`hsv2rgb`, `normalizeColor` and `expandColor` scaling between 255 and 1.
- [`WEVector`](https://docs.wallpaperengine.io/en/scene/scenescript/reference/module/WEVector.html): `angleVector2` and `vectorAngle2`, using degrees.

Official signatures and units are also checked against the official [type definitions](https://docs.wallpaperengine.io/reference/lib.sceneScript.d.ts). Where those sources do not specify a boundary, this runtime chooses clamped cubic Hermite smoothStep, an inclusive step for equal edges, algebraic reversed edges, periodic hue wrapping, grayscale hue zero, color scaling without clamping/rounding, and mathematical +X toward +Y angles with `atan2` output in [-180,180]. These are explicit local conventions, not verified Windows behavior.

Dynamic `import()`, `import.meta`, top-level await and direct `eval()` in a module containing imports are rejected. Asynchronous event results, remaining official events and unimplemented scene/engine APIs still fail explicitly. Static modules do not enable effects, shaders, particles, audio, 3D, timeline/puppet animation or arbitrary external resources. Unlit 2D image rendering retains all existing inspector and frame-validation restrictions.

## Bounded 2D parent hierarchy

Version 0.12 supports image nodes and strictly recognized transform-only nodes, including children preceding their parents in the scene array. Local matrices use translation × Z rotation × signed XY scale; parentWorld × local composition retains the complete affine matrix, including shear produced by nonuniform ancestor scale and child rotation. Zero and negative scales are valid for rendering. Effective visibility is the AND of the node and all ancestors. Image tint, opacity and quad size remain local and are not multiplied by ancestors; composition still follows the original scene array, not tree traversal order. Transform-only nodes do not draw and expose only origin, angles, scale and visible to bindings/scripts. Their transport-only size=1×1, white tint and alpha=1 placeholders are immutable and are not image controls.

`getParent()` returns the direct parent or `undefined` at a root. `getChildren()` returns immediate children in scene-array order. `setParent(parent, adjustTransforms=false)` accepts an existing layer object, ID or name; `undefined` detaches to a root. Without adjustment, local values stay unchanged. With adjustment, the runtime preserves the previous world matrix only when the new local result can be represented by supported 2D translation/rotation/scale. Singular parent inversion or required local shear is rejected before changing the live graph. Full world shear is renderable; arbitrary local shear is not a new editable property. Attachments and additional parent/layer APIs remain unsupported; these are bounded local semantics, not a Windows parity claim.

Inspector, worker and Swift frame publication reject missing/self/cyclic parents, duplicate IDs, more than 512 nodes, ancestry exceeding 64 nodes (root depth 1), nonfinite/out-of-range local values, and world matrix components above absolute 1e12. Every returned frame preserves node identity/kind/dependencies and validates the complete changed graph before pixels publish. This does not enable arbitrary empty object types, 3D parents, effects, animation rigs or camera parallax. Default parallaxDepth `1 1` is treated as inert only with explicit global camera parallax disabled; unsupported camera behavior remains a diagnostic.

The original `Tests/Fixtures/SceneHierarchyWallpaper` uses image → inner transform → animated transform ancestry, a local module, child-before-parent ordering and genuine world shear. [Integration evidence](../../../evidence/scene-parent-integration/result.json) records two real default-Bundle helpers and virtual previewOnly desktop hosts: parent visibility produces exact independently rendered background pixels; group scale, image color and opacity wait for both hosts' actual pixels; local and world transforms are checked; bad graphs/helper failures preserve old sessions; whole-project/override deletion and teardown leave no child processes. Separate affine/pixel checks are in [scene-hierarchy evidence](../../../evidence/scene-hierarchy/result.json). None of these tests changes the real desktop, lockscreen or account, and they do not establish complete Scene compatibility.

## Runtime and actual author-setting acknowledgement

`SceneWallpaperRuntime` connects supported static and scripted scenes to owned library imports, native previews and desktop sessions. For scripts, a separate JavaScriptCore process handles named `init(value)`, `update(value)`, `applyUserProperties(properties)` and `resizeScreen(size)` exports, restricted `Vec2`/`Vec3` and recognized 2D layer properties. A defined event return replaces its attached target; `undefined` preserves in-event layer writes. This is the implemented subset contract, not a claim that all Wallpaper Engine event/API semantics are reproduced.

The first scripted load waits for configure/init, the initial full raw user-property callback, a current-time update when present, strict Swift validation of the complete layer states, off-main composition and native host pixel publication. Later callbacks receive changed keys. Color metadata preserves actual `Vec3` values, while text remains text. Direct bindings and supported `scriptProperties` user mappings update the live helper state. An init-only mapping without a later update or callback consumer stays read-only. AuthorPropertyServices intersects genuinely observed capabilities across active same-item hosts and acknowledges saved changes only after the matching hosts publish real pixels, including an update with zero frame time when needed. Failed hosts retain their last image and observed repairable capabilities; deletion disposes matching hosts and tombstones the item.

PNG/JPEG textures are predecoded once to bounded straight RGBA. Script frames reuse cached textures and validated dependencies without re-reading the inspector or files. One step/composition is in flight at a time, with a 30fps scheduling ceiling and no catch-up queue; actual frame rate depends on workload. Pause stops future updates, resume excludes paused wall time, and author updates while paused publish one current-time frame without advancing runtime. Generation/cancellation guards reject late images. `setAspectFill` redraws cached pixels only. Static scenes start no helper or timer.

The helper has request deadlines, bounded IPC messages and a sampled RSS watchdog. It exposes no native filesystem/network bridge to scripts, but runs with the current user's process privileges: there is **no OS sandbox or hard heap limit**. An RSS sample/termination policy cannot prevent every transient allocation. These controls do not establish full isolation or complete Scene compatibility.

Desktop `applyAndWait` stages target Scene sessions before replacing the prior wallpaper; unsupported/cancelled/superseded work preserves the old sessions and assignments. Static pixel/deletion integration is recorded in `evidence/scene-desktop-integration.json`; actual process, frame, author-ACK, pause, cancellation and infinite-loop tests are in `evidence/scene-script-runtime/` and `evidence/scene-script-worker.json`. The dynamic desktop-controller integration has separate real-helper/two-virtual-display evidence in evidence/scene-script-desktop-integration.json. Native CUA checks cover preview animation, pause/resume, author change/reset, application to an isolated display session, floating details layout and a frozen background; they do not prove Windows parity or physical multi-display behavior.

## Host environment and resolution changes

The helper exposes actual project `engine.canvasSize`, defensive typed copies of current `engine.userProperties`, and host-supplied physical backing pixels through `engine.screenResolution`. Native displays use the active CGDisplayMode pixel dimensions with orientation; preview hosts observe their owning NSWindow screen, rather than substituting view points or the offscreen render-buffer dimensions. Desktop and wallpaper previews share wallpaper mode, desktop-device predicates, and non-editor/non-screensaver flags. `timeOfDay` uses the local 24-hour clock in [0,1), independent of animation time.

Startup configures facts for init and does not fabricate a resize event. A changed resolution sends `resizeScreen(Vec2)`; duplicate sizes do not. Property and screen mutations use a bounded main-actor FIFO, including fast A-B-A and load-in-progress changes. The caller waits for the actual event, strict frame validation and pixel publication, including while paused. Cancelled queued work is removed; disposal wakes pending calls and terminates its own helper.

[Environment evidence](../../../evidence/scene-script-environment.json) separates a real Retina window's backing-pixel provenance and duplicate native notifications from explicit offscreen/virtual-display resolution changes. Physical display hotplug/rotation is still not an accepted hardware test. Destroy, general-settings, cursor/media events and the remaining engine APIs are still unsupported. The independently tested Metal image/pass prototype has not been selected by SceneWallpaperRuntime and does not enable Wallpaper Engine shaders or effects.

## Bounded native Scene effects and the 3820212613 audit

The native renderer supports bounded 2D sphere/box emitters, random lifetime/size/velocity/color/alpha/Z rotation, movement with gravity/drag, fades and size/color curves. The advanced Metal path adds velocity-facing sprite trails, connected ropes with Catmull-Rom subdivision and scrolling texture UVs, static particle children, original 60 Hz curl-field turbulence, alpha oscillators and mouse-linked control-point force. It maintains deterministic bounded state per inspection identity, stops active time while paused, and resets on reload. Particle data is not changed into a pre-rendered movie or static poster. Unknown operators, event children, unsupported flags/control-point modes and arbitrary custom material state still reject the whole project. R8 albedo is white with red-channel alpha and RG88 albedo is linear grayscale with green-channel alpha, following the documented ConvertTexture0Format convention; raw noise, gradient and normal data are kept separate.

The advanced path uses linear RGBA16Float framebuffers. Actual source textures are uploaded once per retained inspection context, while current-time SceneScript results and particle geometry update. Ordered refraction takes a snapshot of preceding layers and samples it using the real normal map and authored refraction amount. LDR bloom thresholds at full resolution, then uses a bounded blur pyramid before final sRGB encoding. Only the built-in lightshaft shader variant whose actual packaged vertex/fragment hashes match the implemented native formula is accepted; point homography, radial/corner modes, gradient/noise texture reads and authored time/shape parameters execute. Downloaded GLSL is never compiled or executed.

These are original local implementations. PRNG, spawn phase, continuous drag, fixed-step curl noise, spline/UV details, refraction response and bloom/filter/color-space math have not been compared pixel-for-pixel against Windows. `SceneWallpaperInspection.fidelityNotes` records these limits; successful compatibility rendering is not original-engine equivalence. HDR, arbitrary shaders, timeline/puppet geometry, unsupported particle event/control behavior and true 3D rendering remain fail-closed. Max count is 2048 per particle system, pre-simulation/lifetime 60 seconds, emitter rate 1000/second, 8192 encoded draws and 512 Mi estimated sample-work units per advanced frame. At most three bounded simulation/texture contexts are retained. Native input snapshots expose a copied `input.cursorWorldPosition` from the actual host content rectangle and inverse camera transform; missing host coordinates remain unknown.

`SceneEngineAssetBundle` is an explicit optional dependency: canonical private root, manifest provenance string, SHA-256 map and optional verified PKG paths. Workshop resources always win. Only allowed material/shader resource namespaces may fall back; project configuration, model and script dependencies never do. Loose engine assets are hashed on read, engine packages are hashed then indexed without extracting files, and changing digests reject. This reader does not log in or download resources itself; the authenticated Steam content broker supplies a verified bundle.

The actual downloaded `栖川渡-4k原画` project (workshop 3820212613) has four image layers, seven particle nodes and two procedural lightshaft shapes. Its three image textures decode as actual static TEXB0004 PNGs, including the 3840×2160 base, 512×512 additive glow and 195×98 blink layer. Its seven missing engine textures are `particle/halo`, `particle/beam/beam_1`, `particle/fog/fog1`, `particle/beam/hose_2`, `particle/beam/hose_2_normal`, `util/noise` and `gradient/gradient_iridescent`. The known Steam installation paths were absent. Production inspection still blocks until real resources are supplied through the explicit verified bundle; synthetic fixtures are never registered as a fallback.
