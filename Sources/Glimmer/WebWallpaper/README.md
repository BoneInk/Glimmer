# Local Web wallpaper runtime

`@MainActor WebWallpaperRuntime(projectURL:entryURL:propertiesJSON:)` validates a local `project.json` location, HTML entry and scalar payload without loading. Embed `runtime.webView`, then call `load()`. Call `dispose()` before discarding; it stops loading/media, removes handlers/delegates and clears the document. A disposed instance cannot be reused. `reload()` preserves the latest desired settings and starts a fresh document handshake.

`propertiesJSON` is the already merged author property dictionary, for example `{"accent":{"type":"color","value":"1 0 0"}}`. It does not parse project metadata or persist overrides. Supported values: bool, color (three space-separated normalized components), slider, combo, textinput. Without an explicit resource manifest, file/directory keys are excluded and reported in `unsupportedPropertyKeys`. With a manifest, file and ondemand directory values must be empty or exact granted virtual paths; fetchall directory properties use their dedicated callbacks. The runtime itself exposes no native picker or arbitrary path bridge. Unknown types or invalid scalar values throw before reaching JavaScript.

The page receives one complete `wallpaperPropertyListener.applyUserProperties` delivery, then only changed property definitions. Normal assignment of a late global listener or late listener method triggers the handshake without polling. Authored async callbacks serialize; pending updates coalesce. Setting custom accessors, redefining the global property or installing a sealed listener after readiness is outside this compatibility contract. Property-key deletion has no synthetic removal event; the importer should supply a stable project schema with merged values/defaults.

`try await applyPropertiesAndWait(data, timeout: 5)` waits for the current document's authored `applyUserProperties` callback to return/resolve. A document token, captured revision and canonical complete payload identify acknowledgement; delivery count is not used. The last successfully consumed unchanged payload succeeds immediately without another callback only when it also remains the current desired payload and its consumed revision covers the latest sent revision. Returning to cached A while async B is in flight waits for A to be consumed again. A newer property request supersedes the previous waiter with `CancellationError`; caller cancellation, callback error, timeout, reload and dispose explicitly throw. An old superseded async callback error does not fail its successor. One waiter is held per runtime. Timeouts are finite, greater than zero and at most 60 seconds. Acknowledgement means the author callback completed; it cannot prove a dishonest author changed its pixels. This method does not persist settings, and the parent coordinates multiple live hosts.

`configureResourceManifest(manifest)` installs the shared Sendable manifest produced by `AuthorPropertyAssets`. Call it before `load()` and before applying file/directory property values. First configuration permanently binds this runtime to `manifest.itemID`; another item needs another runtime. All asset URLs must be regular non-symlink managed copies inside the canonical manifest root. POSIX realpath matches the asset producer, with only Apple /tmp↔/private/tmp and /var↔/private/var aliases normalized; Foundation alias rewriting cannot reject a legitimate managed manifest. Granted response MIME comes from the exact validated virtual basename, because physical vault files may have no extension. Only opaque `__gw_assets__/<token>/<name>` values and directory descriptions reach JavaScript; native root/file URLs never do. A changed asset map cancels outstanding scalar ACKs and invalidates their cache.

Common authored `'file:///' + property.value` use is translated only for this opaque namespace. Public document-start hooks cover img/media/source/poster property setters, setAttribute, CSS background and other common url() properties/setProperty/insertRule, fetch, Request, XHR and Audio construction. A parsed markup/style mutation fallback exists, but is not a general browser URL interceptor: worker realms, srcset, unusual CSS escapes, custom browser APIs, authored overridden setters and an already-created native file URL object are outside the compatibility promise. Arbitrary file:/// paths remain blocked. Each document receives a fresh URL nonce; the handler additionally requires an exact granted token/name. Revoked grants are removed, queued reads are epoch-checked, responses use no-store, and reload invalidates old document URLs. Previously displayed content cannot be erased from an author's own memory.

Ondemand directories implement `wallpaperRequestRandomFileForProperty(propertyName, callback)` with `callback(propertyName, virtualPath)` and an empty path when unavailable. Only current authorized members can be returned. Fetchall directories deliver initial/all changed files to `userDirectoryFilesAddedOrChanged(propertyName, paths)` and revoked paths to `userDirectoryFilesRemoved(propertyName, paths)`, with content identities detecting changes. `configureResourceManifestAndWait(manifest, timeout: 5)` separately waits for those authored directory callbacks, rejects their exceptions, and throws on supersession/cancellation/timeout/reload/dispose. It does not substitute for file/ondemand `applyPropertiesAndWait`. The producer refreshes managed copies explicitly; the renderer does not watch external directories or acquire new permissions.

Listener-less pages reach ready after DOM readiness. `canApplyUserProperties` and `canApplyDirectoryProperties` report actual observed authored methods before invocation, including when the first callback throws; failed hosts retain those observed flags for explicit recovery attempts. Capability observation never marks consumption successful or changes failed to ready; a ready page without listeners never falsely acknowledges scalar consumption. Parent editing capabilities should use these flags together with ready/paused state.

`setGeneralPropertiesJSON` accepts only `{"fps":30}` with fps in 1...240. Desktop, preview and live lock-screen hosts install the same `requestAnimationFrame` scheduler at document start, so the cap also applies when the author ignores `applyGeneralProperties.fps`. Live updates change that scheduler and the authored callback without reloading the page or changing its media timeline. Fractional general-property values use the same truncated integer cap as `frameRateLimit`. The scheduler batches callbacks on WebKit's display clock; it cannot exceed that clock's frequency. Inactive-window scheduling is disabled because wallpaper windows normally sit behind other apps. This is an animation callback cap, not a total GPU-work or video-decoder cap: native videos, CSS animations, workers and timers keep their own clocks. No FPS derivatives, media reloads or source changes are introduced.

Settings and `setPaused` can be called before `load()`. Pause suspends the live RAF scheduler as soon as the host state reaches the page, cancels its outstanding native RAF, and preserves uncalled author handles for resume. An initially paused document installs that state before author scripts run, with one explicit first-frame exception: at most one initial author RAF batch is allowed so common RAF-only canvases can paint. Nested requests remain pending, with no additional native RAF wakeups while paused. Resume/pause cannot renew that per-document budget. This finite bootstrap cannot guarantee a completed first image for arbitrary asynchronous authors. Resume starts on the next display frame without replaying missed frames; cancelling a pending handle remains effective across pause/resume. Host scheduling is independent of serialized async author callbacks. Timer/network-backed property promises can still complete and acknowledge while paused. An author callback that explicitly awaits RAF remains pending until resume; the existing property acknowledgement timeout still applies, and the runtime never runs hidden frames to force its completion. Pause also calls the official cooperative listener and WebKit's public HTML media suspension API. CSS animations, workers and timers retain their clocks. States and `lastError` expose navigation, uncaught JavaScript, missing script resources and WebKit process errors. Optional resource failures and CSP denials remain nonfatal, deduplicated `diagnostics` (at most 64 per document); resource URLs omit credentials, query strings and fragments. The preview exposes these hints separately from fatal errors.

The default standalone runtime requires a gesture for audible media. Desktop hosts explicitly allow authored audio autoplay and apply the saved mute setting before loading; the main-window sidebar can change native page output mute without reloading the document. Previews and lock-screen renderers force native output mute while allowing media frames to advance. The guarded WebKit `_setPageMuted:` / `_mediaMutedState` adapter controls the audio-output flag, preserves unrelated flags, and throws if native mute state cannot be confirmed. This SPI is checked at runtime and is not a public WebKit API. Mute covers HTML media and Web Audio output; Web volume scaling is not provided. Author scripts can still choose not to start their audio or require their own interaction.

Desktop hosts observe mouse moves, left-button clicks/drags and wheel events over the exposed desktop without consuming Finder events. Covered application windows do not receive duplicated wallpaper clicks. The page receives normalized PointerEvent/MouseEvent/WheelEvent input through a document-start bridge, including bounded move delivery and virtual pointer capture during drags. These DOM events are untrusted; native CSS hover, trusted-gesture-only controls and keyboard input are not guaranteed. Local navigation, popup and resource restrictions remain enforced. Preview input stays local to its own WebKit view.

The nonpersistent WebKit view uses a custom local URL scheme. Each request checks its project or explicit grant boundary and opens every relative component with openat/O_NOFOLLOW, rejecting traversal and symlink replacement. Binary assets are served in 64 KiB chunks with single-byte-range (206/416) and HEAD support; video size is independent of the per-chunk allocation. HTML transformation retains a 32 MiB document limit, and concurrent requests remain limited to 16. Cancelled tasks and superseded resource epochs stop delivery before another chunk. Single-track, unencrypted VP9 profile-0 WebM video is served through a lossless ISO-BMFF container adapter. This avoids the reproduced WebKit WebM second-loop stall while retaining the exact compressed samples, source geometry, variable timestamps and native HTML media looping. The request URL and author files/scripts are unchanged; the response correctly identifies the derived media as `video/mp4`, including HEAD/range lengths. Consumers that parse fetched container bytes must honor that MIME type. Encoded samples are streamed without decoding/re-encoding or periodic seek/reload logic. Audio/multiple tracks, alpha, lacing, unsupported track transforms/profiles and files beyond the 2-GiB compatibility-cache budget stay on the original WebKit path instead of losing content. The private, content-addressed process cache is created outside project/staging roots, uses atomic writes and bounded reads, checks source inode/size/timestamps, reuses output between runtime instances and prunes older committed entries. An invalid/truncated cache is rebuilt. `scripts/test-webm-container.sh` tests timestamps, packet preservation, cache invalidation/cancellation, unsafe paths, truncation and a 300-MiB resource.

The HTML receives an early restrictive CSP allowing local scripts/styles/assets, inline/eval scripts needed by existing wallpapers, and data/blob media. Remote resources are disabled by default; explicit `allowHTTPS` adds HTTPS resources while child frames, forms and objects remain denied. The per-wallpaper `webAllowHTTPS` preference rebuilds desktop and preview documents when changed and is used by live lock screens. Unset preferences keep all three contexts offline. Top-level navigation is restricted to the entry and no popup/camera/microphone permission is granted. Native messages only report readiness, acknowledgements and errors; they have no shell/file operation capability. This is a resource policy, not an OS sandbox or a guarantee against hostile WebKit exploits or compromise of the managed root or its ancestor directories. HTTPS access does not bypass CORS, service authorization or missing browser features. `wallpaperRegisterAudioListener` provides 128 silent samples at up to 30 callbacks per second, with at most one async callback in flight; pause, unregister, replacement and page exit bound its lifecycle. Media listener registration accepts the standard status/properties/thumbnail/playback/timeline callbacks, but only status receives `{enabled:false}`; metadata is never manufactured. Capabilities explicitly report no system audio capture or system media integration. Binary plugins and real system-audio visualization remain unsupported. Scene/SceneScript use a separate native renderer and isolated helper; they are not executed in this WebKit component (see ../SceneWallpaper/README.md for its supported subset).

Run `scripts/test-web-wallpaper-runtime.sh` for a real visible WebKit GUI probe in a temporary signed app without production PlugIns. It writes `evidence/web-wallpaper-runtime/probe.json`; temporary app/fixture/synthetic secret are removed on exit. Tests include real file-switch pixels, local/granted H264 playback, fetchall/ondemand callbacks, stale URL/token rejection and post-authorization symlink replacement. No wallpaper, registration or system preference is changed.
